# The user opens a Notebook folder, not a single SQLite file

The app asks for a folder (`showDirectoryPicker`) holding `notebook.sqlite` and a `backups/` subfolder, rather than for the `.sqlite` file itself. A File System Access file handle can only rewrite that one file. Daily and pre-upgrade Backups need to create sibling files, which only a directory handle allows. We rejected keeping the file handle and offering only a manual "Download a copy". With nothing installed and no sync, on-disk Backups are the only protection against a bad save or a broken migration. The cost is that the user can't just double-click or pick an existing `.sqlite` file. To open one (a Backup, say), they put it in a folder as `notebook.sqlite`. See [How does saving stay safe?](https://github.com/RemusAgarbicean/notebook/issues/8).
